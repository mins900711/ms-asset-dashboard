# 적립식 VR 관리

GitHub Pages `/vr/`에서 실행하는 민수·보배 전용 VR 관리 앱입니다. 입장 비밀번호 하나로 두 계좌를 조회하고 편집합니다. 이메일 계정이나 공개용 화면은 사용하지 않습니다.

- 최초 비밀번호는 기존 자산관리 페이지의 편집용 비밀번호를 서버에서 복사한 검증값으로 설정했습니다. 실제 비밀번호는 소스에 포함되지 않습니다.
- 설정의 `입장 비밀번호 변경`은 VR에만 적용되며, 변경 시 다른 입장 세션을 취소합니다.
- 비밀번호 입력란은 숫자 키패드와 숫자 입력만 사용합니다. 삼성 브라우저에서는 자산관리 페이지처럼 처음 렌더링할 때부터 text + numeric 입력과 점 가림을 사용합니다. 포커스 후 입력 종류를 바꾸지 않으며, 점 가림을 지원하지 않는 브라우저는 처음부터 기본 password 입력을 사용합니다. 앞자리 0은 보존됩니다.
- 비밀번호 검증은 서버에서 처리하고 5회 실패하면 5분간 잠급니다. 입장 토큰은 해당 탭에서 최대 8시간 유지됩니다.
- `vr_private`의 테이블은 직접 읽고 쓸 수 없습니다. 공개 `vr_gateway`는 SECURITY INVOKER이며 비공개 구현이 토큰을 검사한 다음 데이터에 접근합니다.
- 변경사항은 자동 저장합니다. 서버 revision이 달라지면 덮어쓰기를 중지합니다. 임시 기록은 sessionStorage에 보관하며 탭 종료 전 저장 상태를 확인하거나 JSON 백업을 내려받습니다.
- 배포 HTML에는 비밀번호, 해시, 입장 토큰, 실제 자산 기록이 없습니다. 실제 기록은 비밀번호 확인 후 서버에서 가져옵니다.
- 엑셀 이관 시 완료된 과거 회차와, 사용자가 적립 완료를 확인한 최신 진행 회차의 계좌현황을 구분해 반영합니다. Done=N이라는 이유만으로 이미 적립한 금액이나 현재 V를 제외하면 안 됩니다. 사용자 확인 전에는 N행의 적립금을 실제 입금으로 간주하지 않습니다.

## 거래 흐름

격주 화요일 점심에 RP 매도 → 직전 월요일 종가와 마감 기간의 V 기준 TQQQ 거래 → 계좌별 $500 환전 → 잔여 달러로 14일 RP 매수 순서로 진행합니다. 매매 전에 다음 기간 V로 이동하지 않습니다. 완료 시 다음 V는 `거래 기준 V × ROUND(1 + 최종 RP ÷ 거래 기준 V ÷ 10, 3) + 이번 적립금`으로 갱신합니다. 주문 한도는 이미 보유한 Pool의 75%이며, 아직 환전하지 않은 이번 적립금은 한도에 더하지 않습니다. 계좌별 숫자 입력은 실제 거래수량과 최종 RP 매수금액 두 개입니다. 증권사 주문은 사용자가 직접 합니다.

## 배포 파일

- `index.html`: Pages 배포본
- `backend/password-gate.sql`: 최초 설치한 비밀번호 방식 스키마와 RPC. 이미 설치된 프로젝트에서 다시 실행하지 않습니다.
- `backend/vr-close.ts`: 입장 토큰 확인 후 TQQQ 종가를 조회하는 Edge Function. verify_jwt=false이며 함수 자체에서 vr_gateway의 세션 검증을 수행합니다.

## 검증

계산 테스트 16개와 기존 엑셀 대조를 통과했습니다. 서버에서 비밀번호 검증, 실패 잠금, 익명 직접 접근 차단, 저장·조회, revision 충돌, 비밀번호 변경과 세션 폐기, 잠금 기능을 시험했습니다. 시험 데이터와 임시 비밀번호 변경은 트랜잭션 종료 시 롤백했습니다. 프런트엔드는 잠긴 화면에서 기존 기록을 표시하지 않는 것과 비밀번호 오류·서버 조회 실패 시 열리지 않는 것을 확인했습니다.

## 일별 종가 자동 누적

TQQQ와 SPY의 미국 거래일별 종가는 브라우저가 닫혀 있어도 수집됩니다. Supabase Cron의 `vr-daily-close-and-retry`가 UTC 월~금 22:20과 23:20에 실행되며 한국시간으로 화~토 07:20 및 08:20입니다. New York 거래일과 장 마감 여부는 수집 함수가 확인합니다.

- `supabase/daily-prices.sql`: 가격·상태·분할 이벤트 테이블, 입장 토큰으로 보호되는 읽기 RPC, service_role 전용 쓰기 RPC와 작업 키 검증, Vault 기반 스케줄러입니다. 최초 설치용으로 이미 설치한 DB에 재실행하지 않습니다.
- `supabase/functions/vr-daily-prices/index.ts`: 수집 함수입니다. verify_jwt=false이며 Vault 작업 키 또는 유효한 VR 입장 토큰으로 자체 인증합니다. service_role 키는 서버 환경에서만 사용합니다.
- 과거 엑셀 DB는 중복 날짜와 실시간 현재가 행을 제외하고 가져왔습니다. 미국 거래일 종가와 기존 달력일 이월 데이터를 구분합니다. 서로 다른 원본의 유의미한 가격 차이 5건은 2026-10-27 Investing.com 과거 종가를 기간 지정해 대조했습니다. 3건을 수정하고 2건을 유지했으며, 모두 확인 완료로 표시했습니다. 수정 전 값·다른 엑셀 값·조회 출처는 daily_prices.verification에 남겼습니다.
- 신규 수집은 최근 50일을 재조회하여 누락을 보충합니다. 장중 값, 통화·종목 불일치, 7일 넘은 공급 응답은 거부합니다. 실패 시 기존 데이터를 유지하고 상태를 표시합니다. 장기 장애가 50일을 넘으면 별도 과거 구간 재수집이 필요합니다.
- 가격은 날짜·종목을 기본 키로 보관합니다. 공급 가격이 기존 값과 2센트 넘게 다르면 기존 값을 보존하고 충돌로 표시합니다. 주식분할이나 관련 가격 충돌은 자동 거래 기준 적용을 막습니다.
- 입장 후 홈페이지 평가는 최신 종가를 사용합니다. 주문 계산은 해당 격주 회차의 월요일 종가를 사용합니다. 수동 확정 가격이나 진행 중인 거래의 기준은 자동으로 덮어쓰지 않습니다.
- `종가` 메뉴에서 가격 그래프·일별 표·수집 상태를 확인하고 CSV를 내려받거나 지금 수집을 요청할 수 있습니다. 수동 재수집은 15분 간격으로 제한됩니다.

소스는 `src/`, 조립기는 `tools/build.cjs`에 있습니다. 저장소의 `vr` 폴더에서 `node tests/engine.test.cjs`, `node tests/daily-prices.test.cjs`, `node tools/build.cjs`로 검증·조립합니다. 배포 파일은 `/vr/index.html`입니다. 일별 가격 테스트의 TypeScript 제거 API는 Node 24에서 검증했습니다.

검증한 내용: 수집기를 실제 서버 작업 경로로 두 번 실행하고 중복 없는 저장을 확인했습니다. 휴장 대체 종가, 장중 제외, 서머타임·겨울 시간, 분할, 잘못된 공급 응답, 가격 접근 권한, 월요일 주문 가격과 일별 평가 가격의 구분을 시험했습니다.

## 엑셀 계좌현황 체크포인트

`tools/excel_checkpoint.py`는 사용자가 적립 완료를 확인한 거래 회차를 읽는 오프라인 이관 도구입니다. 현재 기간은 Done=N이어도 이미 V 갱신과 적립이 반영되어 있을 수 있습니다. 마지막 Y행만 기준 잔고로 쓰지 않고, 확인된 현재 행의 V·Pool·보유수량 및 해당 행까지의 적립원금을 함께 가져옵니다. 최신 행은 엑셀 상단의 현재 원금·Pool·수량과 대조합니다.

호출에는 원본 파일, `--account`, `--trade-date`, `--as-of`, `--funded`, `--output`이 필요합니다. `--funded`는 해당 회차의 실제 적립을 확인했다는 의미입니다. 원본 파일은 수정하지 않습니다. 생성 JSON에는 개인 계좌 내역이 있으므로 공개 저장소에 올리지 않습니다. 회차 종료일은 평가기간이며, 사용자가 확인한 실제 거래일과 별도로 보존합니다.

2026-11-03에 진행 회차의 적립금을 제외했던 초기 이관 오류를 정정했습니다. 실제 체결수량과 최종 RP 잔액은 보존하고, 원금·V·기준 Pool 및 이후 회차 계산만 바로잡았습니다. 정정 전 데이터와 근거는 비공개 상태의 `balanceCorrections`에 보관합니다. 단일 상태 revision을 확인해 동시에 저장된 사용자 기록을 덮어쓰지 않습니다.

재발 검증: `python tests/excel-checkpoint.test.py`는 적립 확인이 있는 N행, 잘못된 마지막 Y행 선택, 미래 회차, 상단 잔고와의 불일치를 검사합니다.

2026-11-03 추가 대조에서 마감 기간의 거래 V와 다음 기간의 V 갱신 시점을 분리했습니다. 주문은 `VR.orderPlan`에서 기존 V를 사용하고, `VR.complete`는 실제 최종 RP를 받은 후 새 V를 계산합니다. 기록의 `orderV`는 실제 주문 기준, `v`는 완료 후 다음 거래에 사용할 기준, `vBasisPool`은 이번 환전 적립금까지 포함한 실제 최종 RP 전체입니다. 앞서 진행 회차를 반영하면서 V를 주문 전에 다시 올렸던 판단은 이 규칙으로 정정했습니다.

사용자가 확인한 운용 순서에 따라 다음 V의 Pool은 최종 RP 전체를 사용합니다. 최종 RP에서 이번 $500를 다시 빼지 않으며, RP 잔액이나 원금에 적립금을 중복 가산하지 않습니다. 매매 전에는 현재 V와 기존 Pool로 수량을 정하고, 환전·RP 매수 완료 후 다음 V를 갱신합니다.
